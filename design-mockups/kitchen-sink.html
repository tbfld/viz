Type & scale

What this page is testing: H1–H3, paragraphs, blockquote, inline/block code, lists, hr, a full-bleed image with caption+credit, and margin notes — all at once, so gaps show up here instead of on a real post.

Margin notes, honestly: this is a pure-CSS, no-JavaScript technique (the classic "Tufte CSS" pattern), revised once already. The reference mark inside the sentence is now just a small label with a number — nothing else — so it can never force a line break. The actual checkbox and note text live as siblings right after the paragraph they belong to, not nested inside it, which is also why the number is now reliable (it's a literal value, not a shared counter trying to stay in sync across two separated spots). Wide screens float the note into the right-hand gutter starting right after that paragraph; narrow screens hide it until the label is tapped, then unfold it as a block after the full paragraph — the sentence itself is never interrupted. It's still not pixel-perfect: both notes above float from the same starting point (the end of their shared paragraph) rather than beside their own individual sentence, so the second one visibly stacks below the first. A JS-assisted version could measure each reference's exact position and nudge its note to match — more precise, but a real script dependency. Worth deciding whether "right after the paragraph" is good enough before building further on this.

Authoring, looking ahead: Obsidian already has native footnote syntax ([^1] / [^1]: text), and Quartz renders those as ordinary bottom-of-page footnotes by default. Turning your normal footnotes into margin notes instead — rather than inventing new syntax to type — means swapping in a custom Quartz transform for footnotes. That's a real build step, not a mockup concern, but it's the automation-first path: write footnotes the normal Obsidian way, let the build turn them into this.
